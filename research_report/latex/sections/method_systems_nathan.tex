\subsection{Systems and Controlled Inference}
\label{sec:systems}

Fig.~\ref{fig:systems} shows the three evaluated pipelines. Direct uses
\path{facebook/seamless-m4t-v2-large}, instantiated as
\texttt{SeamlessM4Tv2ForSpeechToText}, with target code \texttt{cmn}; the v2 model
is described in the Seamless report~\cite{seamless2023}. Its resolved revision is
\path{5f8cc790b19fc3f67a61c105133b20b34e3dcb76}. The cascades use
\path{openai/whisper-large-v2}~\cite{radford2023whisper}, with resolved revision
\path{ae4642769ce2ad8fc292556ccea8e901f1530655}, forced to English transcription.
The resulting English text is translated by one of two NLLB
variants~\cite{nllb2022}:
\path{facebook/nllb-200-distilled-600M}, revision
\path{f8d333a098d19b4fd9a8b18f94170487ad3f821d}, or
\path{facebook/nllb-200-3.3B}, revision
\path{1a07f7d195896b2114afcb79b7b57ab512e7b43e}.
Both NLLB variants use \texttt{eng\_Latn} as source and \texttt{zho\_Hans} as
target; generation forces the target-language beginning-of-sequence token.
The source reference transcript is never supplied to the cascade's MT stage.

All clips and accents use the same inference controls: seed 760, greedy
generation with \texttt{num\_beams=1}, \texttt{do\_sample=False} and
\texttt{max\_new\_tokens=256}. Audio channels are averaged to mono and resampled
to 16~kHz when necessary. There is no denoising, augmentation, accent
normalization, fine-tuning or manual correction. Generated text is decoded with
special tokens skipped and surrounding whitespace stripped. This distinction
matters for the later marker checks: an ordinary-token string spelling \unk{}
is different from the tokenizer's special unknown-token ID.

The full runs used Google Colab Tesla T4 GPUs with FP16 model weights. The saved
environment records report Python 3.13.15, PyTorch and torchaudio
\texttt{2.11.0+cu128}, Transformers 4.57.6 and CUDA 12.8.
Each cascade executes in two passes: Whisper processes all clips, its GPU
memory is released, and NLLB translates the saved successful transcripts.
Pilots and a 35-clip timing test assess execution feasibility rather than tune
translation quality. Predictions and runtime records are checkpointed every
ten samples.

Run-level clip IDs are generated from the frozen row order. Before comparing
systems, we check the metadata and ordered-ID SHA-256 fingerprints, unique IDs,
accent counts, source sentences and Chinese references. The repeating
\texttt{sample\_id} identifies a pseudonymous speaker and is not a unique merge
key. The two cascade ASR passes were executed separately; their archived
transcript strings match on all 4,200 clips. Model and dataset fingerprints are
saved, although the full-run records do not include a Git commit hash.

Timing uses wall-clock measurements with CUDA synchronization around each
measured operation. Direct per-clip pipeline time includes audio loading,
preprocessing, generation and decoding. Cascade time is the sum of separately
measured ASR and MT stages, not simultaneous end-to-end latency. Model loading
and warm-up are excluded from these per-clip measurements. Thus timing is an
engineering diagnostic and should not be interpreted as a fully controlled
deployment-speed comparison.
